## New, concrete findings
1. `quiesce()` (main.rs:120-159): when `in_check`, the filter `in_check || m.is_capture() || m.is_promotion()` keeps **all** legal replies, not just captures, recursing to `MAX_PLY` (96) with no SEE/bad-capture filter. This is exactly what let it navigate the forced-check lines (13.exd5+, 24.Bb5+, 27.Qa7+) correctly here, but it's an unbounded blow-up risk: a long non-mating check chain could burn the whole move budget inside one qsearch call, with only the `nodes & 2047` poll as a safety net.
2. No SEE anywhere — `mvv_lva` orders captures but never prunes losing ones; worked because SF cooperated, won't always.
3. `best_move()` (main.rs:161) prints `info depth N score cp X nodes N` but never `info pv ...`, so we can't audit from logs why e.g. Qc3 beat Bd2, and it's a minor UCI-compliance gap.

## Ranked code items (not already in the plan queue)
1. **SEE-based pruning in `quiesce()`** (main.rs:144-158): skip non-check captures with SEE < 0 before recursing. Reduces qsearch node blow-up (finding 1) and gives a real key for future TT/killer ordering. Est. **+15-25 Elo**. Test: `arena.gauntlet` vs current build, 200+ games same depth/time.
2. **Cap non-capture check-evasion recursion in `quiesce()`** to ~4 plies before falling back to `evaluate()`, as a stopgap until real check extensions land. Est. **+5 Elo / mainly a time-safety fix**. Test: synthetic perpetual-check FEN, confirm bounded node count; re-gauntlet for no regression.
3. **Emit `info ... pv <line>`** in `best_move()` by threading a PV vector up through `negamax`. Est. **~0 Elo directly**, unblocks TT/killer debugging, improves UCI correctness. Test: `uv run arena -v` one game, confirm well-formed `pv` lines.
