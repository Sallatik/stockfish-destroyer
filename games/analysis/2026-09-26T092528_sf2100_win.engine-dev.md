## Diagnosis
- **Horizon, not move ordering.** Replaying the ply-39 FEN on `bin/destroyer-engine-v4` reproduces the game exactly: depth 6-7 in ~4.9s, `bestmove b2b4` both times. `best_move`'s root loop (`main.rs:199-230`) searches every legal move to the full target depth each iteration with no root-level cutoff — order changes only how fast a depth finishes, never which move wins at that depth (a fail-low from a tightened window still correctly rejects a move, per the task note this isn't a bug). Full-strength `bin/stockfish` on the same FEN doesn't settle on Qh5+ until depth ~12 (its score keeps flipping between d1h5/d1e2/d1g4 through depth 8) — the payoff is a long forcing queen infiltration, genuinely invisible at 6-7 ply.
- Re-tested on today's build (v5, TT, same 5s budget): nodes-to-depth-7 fall 2.7x (20.0M -> 7.4M), but it still stops at depth 7 and still plays b4 — TT closes part of the gap, not enough of it.
- Rxa6/Rxe6 (ply 53) is cosmetic: both keep a totally winning position; same shallow-search imprecision, where a mop-up/"prefer the bigger win" eval would help.
