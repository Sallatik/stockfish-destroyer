## Diagnosis
1. **Repeated 1–2 ply tactical blindness (ply 29/51/53, ~360cp combined).** At the time of this game there is no TT (verified against commit `c95290d`: plain full-width negamax, `mvv_lva`-only ordering, no hash move, no killers). Each node does `pos.clone()` + `play_unchecked`; with ~30+ legal replies in a piece-heavy middlegame and zero pruning beyond alpha-beta cutoffs, iterative deepening likely stalls a few plies short of seeing `...Nxf4` each time — the same Nh5→f4/e4 fork is missed three separate times, which is a depth/ordering problem, not an eval blind spot.
2. **No mop-up/passed-pawn-push term in `eval.rs::evaluate`.** Once ahead (+200 to +550cp from ply ~30 on), the engine has no incentive to simplify, activate the king, or push the d/b-pawn fastest; it repeatedly plays "safe" quiet moves (Ra1, Nc5, Rd1 over Rxa6) instead of the most direct win, stretching a dead-won position from ~move 90 to mate at move 117. This is exactly the queued "pawn structure/passed pawns/mop-up" item — this game is good evidence to promote it.
3. PVS/aspiration windows are absent so every node re-searches with a full `[-beta,-alpha]` window at the root's children (see `best_move`), compounding #1's node-budget shortage.

Est. **+20–30 Elo**, mainly via faster forced mates against limited-strength SF (fewer chances for SF to swindle in a long ending). Test: build 10 synthetic K+R(+N) winning-endgame FENs, compare plies-to-mate old vs new build.

No new Elo estimate (already queued); this is a targeted regression check, ~15 min.
