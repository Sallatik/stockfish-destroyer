# Stockfish Destroyer

Two-day team challenge: build our own chess engine and beat Stockfish (limited with `UCI_LimitStrength` + `UCI_Elo`) at the highest Elo possible. Full rules: @mission.md. Current status and next steps: @JOURNAL.md.

## Layout
- `engine/`: our UCI engine (Rust, binary `destroyer`). Built into `bin/destroyer`.
- `arena/`: match runner (Python, python-chess). Plays our engine vs Stockfish, saves each game to `games/`.
- `games/`: **committed, append-only.** `<timestamp>_sf<elo>_<win|loss|draw>.pgn` + `.json` metadata; `index.json` is regenerated by the arena; `analysis/` holds post-game reports.
- `web/`: replay UI (Vite + TS + chessground). Serves `games/` as static files.
- `.claude/`: shared agents + skills (committed, same for every teammate and Claude account). Analysis agents run on Sonnet (`model:` in their frontmatter); the loop session itself runs on the model the user picks.
- `campaign.json` + `arena/campaign.py`: always-on runner playing official games (we are white) vs Stockfish in parallel slots, using the frozen `bin/destroyer-official` (`scripts/promote.sh` updates it). The improvement loop is `/loop /improve-round`.
- `bin/`: pinned Stockfish + built engine. Gitignored, created by `scripts/setup.sh`.

## Commands
- Setup (fresh laptop): `./scripts/setup.sh`
- Rebuild engine: `cargo build --release --manifest-path engine/Cargo.toml && cp engine/target/release/destroyer bin/`
- Campaign runner (leave running in a terminal tab): `uv run python -m arena.campaign`; results in `campaign.log`, levels in `campaign.json`
- Single official game: `uv run arena --elo 1600 --color white` (flags: `--games N`, `--time <=5`, `--engine PATH`, `--out DIR`, `--abort-hopeless`, `-v`)
- Promote current build to the campaign: `scripts/promote.sh`
- Quick smoke test (don't commit): `uv run arena --elo 1320 --time 0.2 --out /tmp/sf-smoke`
- A/B test two engine builds: `uv run python -m arena.gauntlet bin/destroyer bin/destroyer-<tag>` (build old versions with `scripts/build-engine.sh <tag>`)
- Replay UI: `cd web && npm run dev`

## Hard rules (from mission.md, don't break these)
- Max **5 s per move** for both players. Never raise `MOVE_TIME` in `arena/play.py`.
- Stockfish strength only via `UCI_LimitStrength=true` + `UCI_Elo`. Stockfish is pinned to sf_17.1 in `scripts/setup.sh`.
- A draw is not a win.
- Every real game gets saved (arena does this) and must stay replayable in `web/`.
- After each game: run the `/analyze-game` skill, which dispatches **both** the `grandmaster` and `engine-dev` sub-agents. Only official games vs Stockfish count as matches; A/B games (engine vs engine) are test games and are not saved.
- Official proof games are played as **white** (draws don't count, white wins more).
- Development must use `/loop`, `/goal` or a dynamic workflow (we use the play → analyze → improve loop).

## Conventions
- Knowledge goes in `JOURNAL.md` (committed), **not** Claude's auto-memory. We switch laptops and accounts.
- Hardware affects strength at a fixed time per move. The arena records it in each game's JSON. Compare results only across the same hardware.
- CPU budget while the campaign runs: gauntlet `--concurrency 6`, at most 4 campaign slots. Final hour: no gauntlets, 6–8 slots.
- Tag engine versions you want to keep (`git tag engine-v3`). The arena records the engine commit in each game.
- Never edit or delete files in `games/`. Only add new ones.
